# Agent notes

- Python 3.11+ project; install the dev extras with `uv venv .venv --python 3.11` and `.venv/bin/pip install -e ".[dev]"`. Geospatial dependencies (GDAL/rasterio, GeoPandas, etc.) can be platform-sensitive; CI provisions them from conda-forge.
- Run checks in CI order: `.venv/bin/ruff check src tests scripts` → `.venv/bin/mypy src` → `.venv/bin/pytest -v`. For a focused test, pass a file or node, e.g. `.venv/bin/pytest -v tests/test_phase2_1_technical.py::test_t2_dark_water_filter_suppresses_humic_water_but_preserves_wet_sand`.
- Tests create synthetic Sentinel-2 rasters in `tmp_path`; they do not need live STAC/INA services. The experiment scripts are separate workflows: `scripts/run_exp_001_parana_medio.py` and `scripts/run_exp_002_validation.py` query public STAC and may download/cache rasters; run them only when that data/network work is intended.
- Main MCP entrypoint is `src/server.py` (`.venv/bin/python -m src.server`); geospatial logic belongs in `src/core/`, shared settings and POSGAR faja mappings in `src/config.py`, and public data contracts in `src/schemas.py`. `PROJECT_ROOT` and `.env` resolution are based on `src/config.py`, not the caller's working directory.
- Keep Sentinel-2 native grids distinct: VNIR is 10 m; SWIR and SCL are 20 m. Reflectance may be resampled bilinearly, but categorical SCL must use nearest-neighbor; calculate reported areas/distances in metric POSGAR 2007 (EPSG:5343–5349), not geographic degrees.
- Treat detections and generated dossiers as candidate evidence, not proof of extraction or illegality; preserve uncertainty/provenance and require official cadastral data plus human verification. In Exp 002, keep validation parameters frozen and do not tune against the independent Diamante AOI.
- Large/generated data is not generally source-controlled: `.gitignore` excludes raster files (`*.tif`, `*.tiff`, `*.jp2`), GeoPackages (`*.gpkg`), and contents of `data/processed/` and `data/reports/`. Avoid adding generated outputs or local secrets (`.env`) to commits.
- `skills/rio-alerta/SKILL.md` contains the domain-specific operating workflow; consult it when operating the MCP server or interpreting an analysis.
